# Gap Closure — GM + DM Workflow

| Gap identified | Production implementation |
|---|---|
| Project automatically active | `epas_create_project()` is atomic and sets `status=active`, `activated_at`, `activated_by`. |
| Stakeholder notifications | Internal assignments generate in-app notifications; linked stakeholder accounts can receive notifications. |
| Designer revision bypassed DM | `epas_designer_submit_revision()` creates `PLAN_APPRAISAL_REVISION_DM_REVIEW` first. |
| Corrective action was only a note | `corrective_actions` + `CORRECTIVE_ACTION_EXECUTION` task provide a real handover. |
| Follow-up RFI DM→DM fake task | Follow-up RFI is created as a real DM inbox item with `FOLLOW_UP_RFI_DM_SCOPE_REVIEW`. |
| GM final approval not handed to DM | `DM_GM_FINAL_APPROVAL_ACK` is created on GM approval. |
| DM delay/escalation missing | `workflow_escalations` + `GM_ESCALATION_REVIEW` implement the branch. |
| Demo stage advancement | Removed from the production entry point. |
| Actor selectors | Removed. Supabase Auth identifies the actor. |
| Authorization/competency/availability | PostgreSQL `epas_eligible_resources()` enforces all three. |
| Document revision control | `plan_revisions` stores controlled revisions and approval state. |
| Audit trail | `workflow_events` records state transitions and actors. |
| Notifications | `notifications` is user-scoped by RLS and generated by workflow RPCs. |
| Live multi-user | Auth + project membership + RLS + RPC transitions. |
